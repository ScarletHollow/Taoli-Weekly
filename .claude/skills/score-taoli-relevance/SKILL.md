# Skill: score-taoli-relevance（按 E 评分锚点对信号六维打分）

## 一、用途

本 Skill 是**分析类** Skill，承接周报方法论 D 分册「每日流程 D5」的**初评**环节：对已经过过滤（E 分册第六节）、去重（D 分册 D5）并建档（A 分册信号 JSON）的**一条候选信号**，按 E 评分锚点手册（E 分册）的六维 3 档锚点逐维判档，输出「判档 + 分值 + 判档理由（含证据）」，再加总出总分与等级，写入信号 JSON 的 `scoring` 字段。

评分结果是**人工终审的参考**，不是最终结论：AI 初评分只写入 signals JSONL 的评分字段，作为 newsletter 正文字句输出是红线（见 D 分册「AI 的边界」）。人工按 D 分册节点 3 对照 E 锚点复核修正后才生效。

**输出归属**：`scoring` 对象写回 A 分册信号 JSON，供 C 分册呈现、D 分册终审与跨周追溯使用。

## 二、输入 schema

### 2.1 必传输入

1. **信号 JSON**（A 分册 schema，单条）——评分事实的唯一来源。评分为本 Skill 需要读取的字段：

| 字段 | 类型 | 评分用途 |
|---|---|---|
| signal_id | string | 结果归属标识 |
| company / brand / product | string | 竞品与业务重合判定 |
| title / summary | string | 事件实质与工作流判断 |
| education_scenario | string | 维度一判档 |
| workflow_stage | array<string> | 维度一、维度三判档（闭环/多步） |
| ai_capabilities | array<string> | 维度三判档（Agent/诊断/规划等能力） |
| new_change | string | 维度三判档（相对上一次的新变化） |
| target_users | array<string> | 维度二判档（教师/学生/家长/教务运营/学校） |
| source_level | enum(S/A/B/C) | 维度五判档 |
| source_url | array<string> | 维度四、维度五证据引用 |
| evidence | array<object> | 各维判档的核心证据 |
| verification | object/null | 维度四、维度五的核查结论参考 |
| limitations | array<object> | 维度一、维度四的保守判档依据 |
| source_type | string | 过滤与判档辅助（official_product_update / policy 等） |
| report_status | enum | 只评 candidate / selected 等已建档信号，不评分未去重事件 |

2. **桃李业务画像**（对象）——维度二判档的唯一参照：

| 字段 | 类型 | 说明 |
|---|---|---|
| business_lines | array<string> | 桃李当前业务线（教学 / 教务 / 招生 / 课后服务等），以 D 执行手册维护的最新清单为准 |
| segments | array<string> | 服务学段（K12 各学段等） |
| customer_groups | array<string> | 客户群（学生 / 家长 / 教师 / 学校 / 区域等） |
| core_priorities | array<string> | 核心业务与在研项目，用于竞品与试点判定 |
| profile_as_of | string | 画像版本日期，避免凭印象拔高 |

> 业务画像**未覆盖**信号所涉情形时，判「中」或「低」并交人工确认（E 分册维度二注）。

### 2.2 输入约束

- **只评分一条**信号；多信号逐一调用本 Skill。
- 输入信号须已完成过滤与去重（D 分册 D5）；未去重事件不评分。
- 输入信号缺字段时，按「证据缺失保守判档」处理（见执行步骤 4），不允许补造事实。

## 三、输出 schema

输出为信号 JSON 的 `scoring` 对象（A 分册 2.2 约定），六维键名固定：

```json
"scoring": {
  "education_relevance": {"tier": "高", "score": 25.0, "reason": "切入核心教学环节且 workflow_stage 呈闭环：……"},
  "taoli_relevance":     {"tier": "中", "score": 15.0, "reason": "……"},
  "workflow_novelty":    {"tier": "高", "score": 15.0, "reason": "……"},
  "verifiability":       {"tier": "中", "score": 9.0,  "reason": "……"},
  "credibility":         {"tier": "高", "score": 10.0, "reason": "……"},
  "industry_impact":     {"tier": "中", "score": 6.0,  "reason": "……"},
  "total": 80.0,
  "level": "本周必看",
  "summary": "判分一句话综述（判档依据 + 主要不确定点）"
}
```

### 3.1 字段约定

- **tier**：`高` / `中` / `低`，每维恰取一档。
- **score**：单维分值，保留一位小数。档位系数：高=100%（取满权重）、中=60%、低=25%。
- **reason**：判档理由，**必须引用证据**（信号字段或 source_url，见 2.3 证据原则）；无证据的判档视为未完成。
- **total**：六维 score 之和，保留一位小数。
- **level**：由 total 映射（见下方 3.2）。
- **summary**：判分综述，点明最关键的判档依据与不确定点（供人工终审快速复核）。

### 3.2 单维分值对照表（E 分册 2.2）

| 维度 | 评分键 | 权重 | 高(100%) | 中(60%) | 低(25%) |
|---|---:|---:|---:|---:|
| 与教育业务的关系 | education_relevance | 25 | 25.0 | 15.0 | 6.3 |
| 与桃李未来的关系 | taoli_relevance | 25 | 25.0 | 15.0 | 6.3 |
| 工作流创新程度 | workflow_novelty | 15 | 15.0 | 9.0 | 3.8 |
| 可实际验证程度 | verifiability | 15 | 15.0 | 9.0 | 3.8 |
| 信息可靠度 | credibility | 10 | 10.0 | 6.0 | 2.5 |
| 行业影响力 | industry_impact | 10 | 10.0 | 6.0 | 2.5 |
| **合计** | total | 100 | 100.0 | 60.0 | 25.0 |

> 实际判分**以逐维独立判档、单维四舍五入后的值加总**为总分；低档合计 25.2 仅为参考，总分=6.3+6.3+3.8+3.8+2.5+2.5=25.2（本 Skill 按此加总）。

### 3.3 等级映射（主文档「进入周报的判断规则」）

| total | level | 周报呈现 |
|---|---:|---|
| ≥ 80 | 本周必看 | 进正文主位 |
| 65—79 | 重点关注 | 进正文 |
| 50—64 | 信息速览 | 进速览区 |
| < 50 | 不进入 | 不进本周报，信号留库备查 |

边界**含下限**：80.0 属「本周必看」，65.0 属「重点关注」，50.0 属「信息速览」。本 Skill 只输出 level 与评分，**不做** selected / rejected 状态流转（流转归属 D 分册 D5 与节点 1）。

## 四、执行步骤

### 步骤 0：前置校验

- 确认信号已完成过滤（E 分册第六节：融资/口号/品牌宣传/旧闻重发应已剔除）与去重（D 分册 D5）；未通过过滤与去重的信号**不进入评分**。
- 确认输入包含完整信号 JSON 与桃李业务画像；缺任一则先补全再执行。

### 步骤 1：读取判档材料

提取信号字段用于各维判档：

- `education_scenario`、`workflow_stage`、`ai_capabilities`、`target_users`、`new_change`；
- `source_level`、`source_url[]`、`evidence[]`、`verification`、`limitations`；
- 对照桃李业务画像（business_lines / segments / customer_groups / core_priorities）。

### 步骤 2：逐维独立判档

按 E 分册第三节六维锚点表逐维判档，**每维只取一档**，顺序固定：

| 步骤 | 维度（评分键） | 权重 | 高 | 中 | 低 |
|---|---|---|---|---|---|
| 2.1 | 与教育业务的关系（education_relevance） | 25 | 切入核心教学环节（备课/授课/练习/测评/个性化学习等）且形成业务闭环 | 作用于明确教育场景、增强其中一步（单点增强，未贯穿流程） | 通用技术、无教育落地（仅宣传「助力教育」，或通用模型能力更新） |
| 2.2 | 与桃李未来的关系（taoli_relevance） | 25 | 与桃李核心业务重合可借鉴，或构成直接竞争 | 明显相关、可试点（相关但非主业直接冲突） | 基本无关（不涉及桃李教学/教务/招生/服务任一环节） |
| 2.3 | 工作流创新程度（workflow_novelty） | 15 | 首次出现的新型工作流，或多步自动化（AI 串联多步、替代/重构一段完整流程） | 在已有工作流中新增重要环节（如新增 AI 诊断、AI 批改环节） | 单点功能增强或口号（单个问答能力提升、无流程变化） |
| 2.4 | 可实际验证程度（verifiability） | 15 | 有真实用户数据（落地数据/财报/应用案例）或可复现演示（可亲测、公开可复现的 demo） | 有明确验证路径但未亲验（有产品页/演示链接/试用入口，执行者尚未实际测试） | 靠厂商自述或传闻（无数据、无产品、无法复现） |
| 2.5 | 信息可靠度（credibility） | 10 | S 级来源（政府/企业官网、产品页、技术文档、财报、正式发布会记录） | A/B 级来源（学校教育局案例、招投标、App 更新、专利论文；或行业媒体线索） | C 级或无法追溯（社交平台、未确认截图、不可溯源转载） |
| 2.6 | 行业影响力（industry_impact） | 10 | 行业里程碑，或头部集体跟进（多个头部跟进同形态、引发行业范围讨论） | 代表一类趋势（该趋势的代表案例，未达集体跟进） | 影响面窄或无（仅个案，无后续） |

### 步骤 3：证据引用与理由书写

- 每维判档理由**必须引用证据**：优先引用信号字段（如 `workflow_stage` 呈现闭环、`source_level=S`、`new_change` 描述、`ai_capabilities` 含 Agent 等），再补 `source_url` / `evidence` 条目。
- 理由格式遵循 E 分册 2.3：
  > 维度五 信息可靠度 = 高（10.0）｜依据 `source_level=S` + `source_url=<官方产品页>`。
- 引用 `evidence` 时写明 fact + source_level；引用 `verification` 时注明核查结论。

### 步骤 4：加总与分级

- 单维分值 = 该维权重 × 档位系数（高 100% / 中 60% / 低 25%），保留一位小数（四舍五入）。
- `total` = 六维 score 之和，保留一位小数。
- 按 3.3 等级映射输出 `level`；`summary` 给一句话综述（核心判档依据 + 主要不确定点）。
- **先逐维判档，再算总分，顺序不可逆**；不允许用总分反推档位。

### 步骤 5：强制进入标记（AI 仅建议）

- 命中 E 分册第五节两类触发（重大政策 / 一级名单直接竞品影响桃李核心业务的变化）时，照常六维评分，另在信号 JSON 的 `special_override` 字段**建议**填写 `{"reason": "重大政策/直接竞品变化", "decided_by": "<待人工>", "decided_at": "<本期日期>"}`。
- 是否强制进入由**人工确认**；强制 ≠ 高分，不改变六维评分。

### 步骤 6：写回与交接

- 将 `scoring` 对象写入信号 JSON 对应字段（A 分册 2.2），随 signals JSONL 落盘。
- 结果供人工按 D 分册节点 3 复核修正；**AI 不自动发布、不自动置 published、不直接产出 newsletter 正文**。

## 五、写作规范

### 5.1 判档纪律

- **六维独立判档，维度间不交叉补偿**：某一维高不得抬高其他维（如「可靠度低但行业影响力高」不能互抵）；不得用总分反推档位（E 分册 2.5）。
- **热度 ≠ 高分**：融资、发布会口号、普通品牌宣传、舆情热议，若无产品/技术/工作流/业务变化，不得加分（E 分册 2.4）。「行业影响力」按行业实际跟进与代表性判定，不按热搜量。
- **边界档取低**：介于两档之间、证据不足以支撑高档时，取低档（证据缺失保守判档，E 分册 2.1）。例如维度二业务画像未覆盖 → 判中或低交人工。
- **S 级 ≠ 全维高分**：`source_level=S` 只支撑维度五；教育实质、桃李相关性、创新性仍须按各自锚点独立判定。

### 5.2 理由书写

- 判档理由写**判定依据 + 证据**，不给空泛结论（不写「因为重要所以高」）。
- 理由中出现的档位与分值须与 3.2 对照表一致。
- 不确定处如实写入 `reason` 或 `summary`（如「未亲测，验证路径明确」），供人工终审决定是否修正。

### 5.3 输出纪律

- 输出结构完全符合第三节 schema：六维各含 `tier / score / reason`，加 `total / level / summary`。
- `score` 保留一位小数；`level` 取 3.3 映射标准值（本周必看 / 重点关注 / 信息速览 / 不进入）。
- 本 Skill 只产出 `scoring`；**不修改** `report_status`、`dedup_key`、`reviewer_feedback`、`special_override`（后者仅步骤 5 允许建议填写）。
- 涉及去重（D5）与发布（节点 4 人工）的内容一律不出现。

### 5.4 红线

- **不自动发布**：本 Skill 不触发任何发布行为，不将信号置为 published（发布归 D 执行手册节点 4 人工操作）。
- **不自动去重**：去重归 D 分册 D5 步骤（读取 dedup_key 做事件级去重），本 Skill 不实现去重。
- **不自动冻结**：候选池冻结归 D 分册节点 1 人工操作。
- **不造证据**：缺字段或不可证伪点按局限记录（`limitations`），不得凭推测拔高档位。

## 六、示例

> 以下为 E 分册第七节的构造案例展示（**非真实事实**），用于演示逐维套用方式。真实评分以输入信号 JSON 的实际字段为准。

**输入**（构造）：学而思（好未来）宣布上线「小思 AI 1对1」AI 个性化辅导产品，基于九章大模型，覆盖学习目标识别、知识讲解、练习、诊断、补弱五环节；`source_level=S`，`source_url=<官方产品页>`；`workflow_stage=[学习目标识别,知识讲解,练习,诊断,补弱]`；有官方演示但执行者未亲测（无真实使用数据）。桃李业务画像：线下教学为主、学生端个性化学习相关。

**逐维判档**：

| 维度 | 判档 | 分值 | 理由（证据） |
|---|---|---:|---|
| 一 教育相关性 | 高 | 25.0 | 切入个性化学习核心环节，且 `workflow_stage` 呈「学习—检测—诊断—补弱」闭环，符合主文档 A1 闭环判据 |
| 二 桃李相关性 | 中 | 15.0 | 学而思为一级名单直接竞品、与学生端个性化学习明显相关可试点；但与桃李核心主业（线下教学为主）不完全重合，不判高，交人工按业务画像确认 |
| 三 工作流创新 | 高 | 15.0 | 首次在头部机构把多环节串联为 AI 1对1 多步工作流（`ai_capabilities` 含 Agent/规划），符合「多步自动化」 |
| 四 可验证性 | 中 | 9.0 | 有官方产品页与演示，验证路径明确但未亲测；人工亲测取得真实使用数据后可升至高 |
| 五 信息可靠度 | 高 | 10.0 | `source_level=S` + `source_url=<官方产品页>` |
| 六 行业影响力 | 中 | 6.0 | 代表「AI 1对1 个性化辅导」一类趋势，多家头部跟进；未达全员跟进的里程碑 |

**输出**：

```json
"scoring": {
  "education_relevance": {"tier": "高", "score": 25.0, "reason": "切入个性化学习核心环节且 workflow_stage 呈闭环"},
  "taoli_relevance":     {"tier": "中", "score": 15.0, "reason": "一级名单直接竞品、可试点，但与桃李主业不完全重合"},
  "workflow_novelty":    {"tier": "高", "score": 15.0, "reason": "多环节串联为 AI 1对1 多步工作流"},
  "verifiability":       {"tier": "中", "score": 9.0,  "reason": "官方产品页+演示，验证路径明确但未亲测"},
  "credibility":         {"tier": "高", "score": 10.0, "reason": "source_level=S + 官方产品页"},
  "industry_impact":     {"tier": "中", "score": 6.0,  "reason": "代表一类趋势、多家跟进，未达里程碑"},
  "total": 80.0,
  "level": "本周必看",
  "summary": "六维中三高三中，总分 80.0 恰在必看边界；主要不确定点为维度四未亲测，人工亲测后可升档"
}
```

> 判档要点：维度二因业务画像未完全覆盖判中不判高；维度四边界档取中；总分 80.0 边界含下限属必看；AI 初评结果由人工终审复核后冻结，发布由 D 分册节点 4 人工完成。

## 七、与其他 Skill / 分册的边界

- **上游**：monitor-education-companies / monitor-china-models（采集）→ classify-education-signal（分类建档）→ 本 Skill（初评）。
- **下游**：write-company-analysis / write-taoli-actions / format-all-staff-newsletter（只读 selected 信号，本 Skill 不产出正文）。
- **来源核查**：verify-source-evidence / check-source-quality 承接来源质量，本 Skill 只消费其结果的 `verification` 字段。
- **去重**：D 分册 D5 步骤（读取 dedup_key），本 Skill 不实现。
- **发布**：D 分册节点 4 人工操作，本 Skill 不自动发布。
- **评分参照**：以 E 评分锚点手册为准；与主文档「进入周报的判断规则」权重总表、A 分册 `scoring` schema 保持一致。
