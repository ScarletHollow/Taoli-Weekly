# write-taoli-actions — 桃李可执行建议区生成

## 一、用途

把本期**已 selected**(含 business 业务层与 tech 技术层)的条目转译为桃李团队**能直接执行的动作**,落到 C 分册 newsletter 的「⑤ 桃李可执行建议」区(2-4 条)。本 Skill 只做「从条目到建议」的提炼与分级,不采集、不评分、不排期。

- **产出位置**:C 周报输出规范 §五「桃李可执行建议」区(技术层之后、附注之前)。
- **输入来源**:A 分册信号 JSON 中 `report_status=selected` 的信号(对应 C 分册业务层 C-Bxx / 技术层 C-Txx 条目)。
- **调用时机**:D 执行手册「节点 2 生成初稿」;建议区内容由人工在节点 3 审核、节点 4 决定是否执行。
- **边界(红线)**:本 Skill **不负责**去重(归 D 分册 D5 步骤)、**不触发**任何发布动作、不把建议区内容自动置为 published;「发布」是 D 分册节点 4 的人工操作,AI 只产出文本。去重、发布相关行为一律不得出现在本 Skill 的执行结果中。

## 二、输入 schema

输入:**本期 selected 条目集**,每条来自 signals JSONL 中 `report_status=selected` 的信号,或已按 C 模板编号的业务层 / 技术层条目。至少携带以下字段:

```json
[
  {
    "signal_id": "SIG-2026-W33-0001",
    "entry_id": "C-B01",                 // 业务层 C-Bxx / 技术层 C-Txx,建议区据此回溯源条目
    "title": "信号标题(≤40 字)",
    "summary": "一句话摘要(≤80 字)",
    "company": "公司", "brand": "品牌", "product": "产品",
    "education_scenario": "AI 进入的教育场景",
    "workflow_stage": ["被 AI 介入的业务流阶段(对齐工作流模板第 3 步)"],
    "ai_capabilities": ["OCR|多模态理解|知识库|推荐|Agent|内容生成|诊断|规划"],
    "new_change": "本次新变化",
    "target_users": ["教师|学生|家长|教务运营|学校"],
    "source_level": "S|A|B|C",
    "source_url": ["来源链接,≥1"],
    "evidence": [{"fact": "核心事实", "source_level": "S|A|B|C", "source_url": "URL"}],
    "verification": {"source_level": "S|A|B|C", "checked_url": "URL", "conclusion": "已核实|存疑|无法核实", "note": ""},
    "scoring": {
      "education_relevance": {"score": 25, "reason": ""},
      "taoli_relevance":     {"score": 25, "reason": ""},
      "workflow_novelty":    {"score": 15, "reason": ""},
      "verifiability":       {"score": 15, "reason": ""},
      "credibility":         {"score": 10, "reason": ""},
      "industry_impact":     {"score": 10, "reason": ""},
      "total": 80, "level": "本周必看|重点关注|信息速览"
    },
    "report_status": "selected",
    "limitations": [{"aspect": "", "note": ""}],
    "recommended_action": ""   // 可作参考线索,不作为建议定稿的既有事实
  }
]
```

- 本期建议**只允许**从上述 selected 条目中提炼,不得凭空引入外部建议。
- 期数 2-4 条;少于 2 条可写 2 条(宁缺毋滥,见下),多于 4 条必须合并或取舍。
- `score-taoli-relevance` 初评、人工修正后的分数只作参考与可解释性支撑,分数本身不进入建议区正文字句(遵循 D 分册「AI 评分不直接进正文」红线)。

## 三、输出 schema

输出:**桃李可执行建议区内容**,直接可粘贴进 C 分册 newsletter 的⑤区。结构为 2-4 条建议,每条含 6 个字段,且**必须**落定四类分级措辞之一:

```json
{
  "section": "桃李可执行建议",
  "actions": [
    {
      "action_id": "AC-01",
      "suggestion": "动词开头的可执行建议(一句话)",
      "reason": "支撑论据,可回溯到来源条目(可引用条目编号)",
      "owner_team": "负责团队(桃李内部)",
      "priority": "高|中|低",
      "verification": "验证方式(如何判断值得执行)",
      "source_ref": "来源条目编号 C-Bxx / C-Txx",
      "category": "可直接借鉴|需自行研发|可购买第三方|暂不值得投入"
    }
  ]
}
```

- **suggestion**:一句话,动词开头(如「试点」「上线」「外采」「立项调研」「暂缓」),≤50 字,直接落到一个动作。
- **reason**:1-2 句,必须引用 A 分册信号字段(workflow_stage / ai_capabilities / new_change / evidence / source_level 等)或 C 条目编号作论据;没有依据的建议不得产出。
- **owner_team**:桃李内部团队(如 课后服务团队 / 教学产品团队 / 技术中台 / 教研团队 / 产品研发),按 D 执行手册业务清单口径,不得写外部团队。
- **priority**:高 / 中 / 低(与四类分级联动,见写作规范第 3 条)。
- **verification**:具体、可度量——如「2-4 周小范围试点,看学生完成率与回测通过率」「申请官方 demo 亲测 3 个教学场景」「对比第三方报价与自研成本」。
- **category**:四类之一,必须给出判据(见写作规范第 2 条),不得模糊或兼写多类。

## 四、执行步骤

1. **读入选定条目**:取本期 `report_status=selected` 的信号;读每条 `title / summary / new_change / workflow_stage / ai_capabilities / education_scenario / evidence / verification / limitations / scoring.total`。
2. **判别桃李相关性(聚类)**:把 selected 条目按「对桃李的价值方向」分组——先看与桃李业务(课后服务、教学产品、教研、招生、教务)的直接关联,再按条目的 `ai_capabilities` 与 `workflow_stage` 判断「桃李可以用它做什么」。聚类后形成候选建议池(通常 3-6 条候选)。
3. **逐条套四类分级**:对每个候选建议,用 C 分册 §五 的四类定义(可直接借鉴 / 需自行研发 / 可购买第三方 / 暂不值得投入)判定分类:
   - 先判断「是否有成熟做法或成熟产品」→ 若有且可照搬 → **可直接借鉴**;
   - 若无现成方案、核心价值需自建 → **需自行研发**;
   - 若市场存在可采购的第三方能力且成本低于自研 → **可购买第三方**(可与「可直接借鉴」「需自行研发」并用,措辞落定时须写明边界);
   - 若本期证据不足、与桃李无交集、或投入产出比不明 → **暂不值得投入**,并写出**重新评估的触发条件**(见写作规范第 2 条)。
   - 每条建议只落定一个主分级;若边界需细分,用括号写明"X 部分可直接借鉴 / Y 部分需自行研发",主类仍在四类之一。
4. **定优先级**:与分级联动 —— 直接竞品进入桃李核心场景 / 评分 80+ 且可低成本试点 → 高;可试点但需验证 → 中;投入产出不明或本期仅线索级 → 低。不给「暂不值得投入」类定「高」。
5. **收敛到 2-4 条**:按「对桃李价值最大 + 依据最扎实」取舍;同类建议合并;留 1 条给「暂不值得投入 / 观察」类(如有),避免建议区全是同质动作。宁缺毋滥,不用弱证据建议凑数。
6. **补全字段并校验**:为每条补 `owner_team / verification / source_ref`,回填 C 条目编号;核对措辞确在四类之内、建议区无自动发布行为。
7. **输出**:按第三节输出 schema 产出建议区内容,交由 `format-all-staff-newsletter` 排版。

## 五、写作规范

1. **只写本期条目能支撑的建议**:不得新增条目之外的臆测;每条建议必须有可回溯的条目(建议区篇幅 ≤ 该期条目数)。
2. **四类分级必须落定且可解释**:四类措辞严格用 C 分册 §五 定义(可直接借鉴 / 需自行研发 / 可购买第三方 / 暂不值得投入)。「暂不值得投入」必须给出**重新评估的触发条件**(如"若 X 上线真实数据后完成率 >Y% 再评估")。
3. **优先级与验证要落地**:priority 高/中/低;verification 给具体指标(时间窗、指标名、对比对象),不写空泛的"持续观察"。
4. **措辞给桃李,不给行业**:主语是"桃李""桃李 XX 团队",以动词开头(试点/上线/外采/立项/暂缓);不评价行业大势、不写厂商广告语。
5. **避免评价性空话**:不用"建议关注""值得期待"类无动作表述;每条必须含一个可执行动词与一个可度量的验证方式。
6. **篇幅**:每条建议 2-3 句(建议一句 + 理由 1-2 句),建议区整段 ≤ 该期正文的 1/3 篇幅。
7. **引用编号**:reason 与 source_ref 必须写 C 条目编号(C-Bxx / C-Txx),不得只写来源 URL。
8. **红线**:不出现自动发布、自动发送、自动推送等行为描述;不出现去重步骤。

## 六、示例

> **构造示例,非本期真实数据。** 仅演示 schema 与写法,不代表任何真实产品功能。

**输入(selected 条目集,节选 2 条)**

- **C-B01**:好未来 / 学而思 / 学习机「错题归因重练」闭环;`workflow_stage=[作业批改, 错因诊断, 补弱]`、`ai_capabilities=[诊断, 内容生成, 推荐]`;S 级来源;scoring.total=86(本周必看)。
- **C-T01**:某国产大模型开放 API 支持文档/视觉 Agent;`ai_capabilities=[多模态理解, Agent]`;S 级官方技术文档;scoring.total=71(重点关注)。

**输出(桃李可执行建议区,3 条)**

```json
{
  "section": "桃李可执行建议",
  "actions": [
    {
      "action_id": "AC-01",
      "suggestion": "试点「错题归因+变式重练」闭环:先外采变式题生成能力,归因模型自研验证。",
      "reason": "学而思 C-B01 已形成「判错—归因—变式—重练—回测」闭环,与桃李课后补弱场景高度重合;其中变式题生成存在成熟第三方能力可外采,错因归因依赖教育数据积累,需自研。",
      "owner_team": "课后服务团队 + 教学产品团队",
      "priority": "高",
      "verification": "2-4 周小范围试点,对比试点班/对照班学生完成率与回测通过率,达标后再决定是否全面立项。",
      "source_ref": "C-B01",
      "category": "可直接借鉴"
    },
    {
      "action_id": "AC-02",
      "suggestion": "调用支持文档/视觉的 Agent API,在作业批改场景做一次 2 周技术验证。",
      "reason": "C-T01 官方开放 API,能力覆盖多模态理解与 Agent;技术中台可低成本接入,判断其能否承担桃李的作文/主观题批改环节。",
      "owner_team": "技术中台",
      "priority": "中",
      "verification": "用 50 份真实作文样例跑批改,对比人工批改的一致性(≥0.8 通过)、单条成本与延迟;不达标则外采或自研方案再议。",
      "source_ref": "C-T01",
      "category": "可购买第三方"
    },
    {
      "action_id": "AC-03",
      "suggestion": "暂缓跟进某海外工具类 AI 教育产品,先记录在观察清单。",
      "reason": "该产品(C-B02)本期仅有 C 级来源与演示视频,无真实使用数据,与桃李主业交集有限;按 E 分册评分不足 50,依据不足以支撑投入。",
      "owner_team": "产品研发(策略)", 
      "priority": "低",
      "verification": "若其发布真实用户数据且覆盖率与桃李目标学段重合度提高,再重新评估;当前不投入资源。",
      "source_ref": "C-B02",
      "category": "暂不值得投入"
    }
  ]
}
```

> 注:示例 AC-01 主类为「可直接借鉴」,内部细分(变式题外采 + 归因自研)在 reason 中写明;主分类仍落定四类之一。
