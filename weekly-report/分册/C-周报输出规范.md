## 〇、分册定位与读者契约

本分册定义**公司全员版 newsletter 的最终交付形态**:让任一「编辑 + AI」协作,都能产出一期结构与风格一致、可直接面向全员发布的成品。

- **面向读者**:方法论维护者 + 单人+AI 协作执行者。执行周报时以 **D 执行手册**为操作入口,本册为写作与交付时的参照。
- **前置条件**:条目的选题与评分由主文档「进入周报的判断规则」与 E 评分锚点手册决定(评分由 score-taoli-relevance 按 E 锚点初评、人工终审修正);信号字段由 A 信号数据手册定义;候选条目的建档由 monitor-education-companies 等采集 Skill 与 classify-education-signal 完成。本册只回答"入选的条目怎么写、排在哪、长什么样"。
- **产出路径**:候选信号(A 分册,由 monitor-education-companies 采集建档)→ 评分(主文档「进入周报的判断规则」+ E 分册,score-taoli-relevance 初评)→ 本册写作(业务层/技术层用 write-company-analysis,建议区用 write-taoli-actions,整体排版用 format-all-staff-newsletter)→ 人工审核后发布。

与相邻分册的边界(避免重复):

- **去重归属 D 分册**:同类去重与跨期去重执行在 D 执行手册 **D5 步骤**,本册不写去重规则。
- **发布归属 D 分册**:最终发布是 D 执行手册**节点 4 的人工操作,AI 不自动发布**。本册只定义成品的结构与内容,不定义发布动作。
- **来源核查归属 Skills**:每条核心事实 ≥1 个 S 级来源的核对由 verify-source-evidence 与 check-source-quality 承载;信息源分级见主文档「信息源分级」。

## 一、一期周报的完整骨架

区块**固定顺序**不可调换,共 6 区:

```
① 期元信息
② 期要点(≤60 字)
③ 业务层正文(3-5 条)
④ 技术层正文(2-3 条)
⑤ 桃李可执行建议(2-4 条)
⑥ 附注(来源与存疑)
```

### 1.1 期元信息(表头,非正文区块)

| 字段 | 填写规则 |
|---|---|
| 期号(YYYY-WW) | 按 ISO 周编号,如 2026-W32 |
| 发布日 | 周一中午或下午(时间节奏见主文档「抓取节奏」) |
| 本期条数 | 业务条数 + 技术条数 + 政策加急条数(若有) |
| 数据窗口 | 本期采集覆盖的起止日期 |
| 审核人 | 人工审核者署名 |
| 发布人 | D 执行手册节点 4 执行人工发布的人 |

示例(仅示格式,非本期真实数据):

```
期号:2026-W32  发布日:2026-08-10
本期条数:6(业务 4 + 技术 2)
数据窗口:2026-08-03 — 2026-08-07
审核人:___  发布人:___
```

## 二、「期要点」写法

- 位置:期元信息之下、正文第一条之前。≤60 字,一段话。
- 结构固定三要素:**【动作方】+【具体动作】+【对桃李含义】**。
- 内容来源:**必须出自本周必看(评分 80+)** 的条目,不允许用 65-79 分条目提炼期要点。
- 作用:让不熟悉 AI 的同事 30 秒读完即知"这周发生了什么、对桃李意味着什么"。

写法模板:

> 本周【动作方】【做了什么具体动作】,【对教育场景的含义】;桃李可【跟进动作】。

示例(构造,非本期真实数据):"【学而思】学习机上线错题归因重练闭环,课后补弱实现自动化;桃李课后服务可先复制'变式重练'一段。"

## 三、业务层条目规范

### 3.1 字段清单

每条业务层条目按以下字段填写(与 A 分册信号 JSON 字段对齐):

| 字段 | 说明 |
|---|---|
| 编号 | 本期唯一,如 C-B01 / C-B02 |
| 标题 | 见 3.2 步骤 1(≤30 字) |
| 一句话要点 | 见 3.2 步骤 2(≤40 字) |
| 企业/产品 | 公司 + 品牌 + 产品 |
| 教育场景 | 对应 A 分册 education_scenario 字段 |
| 工作流变化 | 原流程 → AI 介入后流程(对齐主文档「企业 AI 工作流拆解模板」) |
| 数据闭环 | 是否形成"AI 输出反哺下一轮教学"的闭环 |
| 来源等级 | S/A/B/C(见主文档「信息源分级」) |
| 桃李含义 | 对桃李业务的具体意义 |
| 借鉴分级 | 四类措辞之一(见第五章) |

### 3.2 条目内部 5 步

1. **标题** ≤30 字:直陈"谁 + 做了什么 + 对谁有用",不用修辞与感叹号。
2. **条要点** ≤40 字:一句话说清核心事实。
3. **正文** 2-3 段:首段核心事实,中段工作流变化与数据闭环,末段行业/竞争含义。
4. **桃李含义**:单列,写"桃李可以借鉴/研发/购买/观望"的具体指向。
5. **来源标注**:列出本次使用的来源(S 级优先);存疑处写入附注区。

### 3.3 硬性约束

- **每条核心事实 ≥1 个 S 级来源**(见主文档「信息源分级」);仅有 B 级线索的条目必须回到企业、政府或产品原始页面核查后再写入(由 verify-source-evidence 承载)。
- **篇幅 200-400 字**(正文 2-3 段,不含桃李含义段)。
- 企业自述(S 级)与实际案例(A 级)须区分表述,不得混写。
- 草拟调用 write-company-analysis,人工终审修正后定稿。

## 四、技术层条目规范

### 4.1 字段清单

| 字段 | 说明 |
|---|---|
| 编号 | 本期唯一,如 C-T01 / C-T02 |
| 模型/平台 | 模型或平台名称 |
| 新能力 | 具体能力变化(文档/视觉、Agent 与工作流、生产应用三类,见主文档「国内模型与 AI 平台观察名单」) |
| 教育用途 | 该能力可用于教育的具体用途 |
| 对教育意味着什么 | **必填**:能力对教学/教研/服务流程的潜在影响 |
| 桃李选型影响 | 是否影响桃李的技术选型或产品路线 |
| 来源等级 | S/A/B/C |

### 4.2 进入与篇幅规则

- **准入**:模型能力只有可能改变教育业务时才进入正文(主文档「国内模型与 AI 平台观察名单」);纯参数、榜单、发布会口号一律不写。
- **必须含「对教育意味着什么」**:无此段的技术条目不允许定稿。
- **篇幅 150-300 字**,不超过业务层篇幅。
- 采集与建档由 monitor-china-models、classify-education-signal 承接;写作仍由 write-company-analysis 以教育业务视角拆解。

## 五、「桃李可执行建议」区

- 位于技术层之后、附注之前;每期 2-4 条。
- 只写本期业务层/技术层条目能支撑的建议,不凭空新增。

字段:

| 字段 | 说明 |
|---|---|
| 建议 | 一句话可执行事项 |
| 理由 | 支撑该建议的论据(可回溯到来源条目) |
| 负责团队 | 建议归属的桃李内部团队 |
| 优先级 | 高 / 中 / 低 |
| 验证方式 | 如何验证建议是否值得执行 |
| 来源条目编号 | 对应 C-Bxx / C-Txx |

**措辞分级四类**(沿用主文档「企业 AI 工作流拆解模板」),每条建议必须落定其中一类,不得模糊:

1. **可直接借鉴** — 已有成熟做法,桃李可照搬或轻量改造。
2. **需自行研发** — 核心价值需自建,不依赖外部。
3. **可购买第三方** — 存在成熟可采购的产品/服务,成本低于自研。
4. **暂不值得投入** — 观望即可,同时给出重新评估的触发条件。

建议区写作调用 write-taoli-actions。

## 六、每周条数与取舍

### 6.1 条数

- 每期 **5 ≤ N ≤ 8** 条;宁缺毋滥,不用低质量条目凑数(主文档「周报监测范围」)。
- 分配:**业务层 3-5 条 + 技术层 2-3 条**;重大政策可追加 1 条**政策加急**(经人工强制进入,记录于 A 分册 signals JSONL 的 special_override 字段)。
- 条数在监测比例框架(50% 教育 / 25% 模型 / 15% 政策 / 10% 海外)内分配;某一类别某周无重要内容可少于比例,不硬凑。

### 6.2 取舍优先级(由高到低)

1. **重大政策与直接竞品变化**(人工强制进入)。
2. **评分 80+**(本周必看)。
3. **评分 65-79**(重点关注,有剩余名额时进入)。
4. **评分 50-64**(信息速览,一般不进正文)。
5. **同类去重**(多条同类事件只保留综合最强者;去重执行在 D 执行手册 D5 步骤)。

### 6.3 report_status 衔接

取舍结果写回 A 分册信号 JSON 的 report_status:

- **selected** — 选入本期正文(业务层 / 技术层 / 建议区)。
- **rejected** — 评分不足、重复或经人工终审否决,不再进入;仍保留在信号库备查。
- 本周未选中且未否决的候选,在 D 分册节点 1 冻结时由人定为 rejected(留在信号库),不滞留 candidate(遵循 A 分册「冻结时不得滞留 candidate」规则)。

状态机定义见 A 信号数据手册「精简状态流转」;本册只消费 D5/节点 1 之后的流转结果(selected / rejected / frozen / published),不定义流转。

## 七、简版写作语言规范

目标读者含非技术全员。三条规则:

### 7.1 首句结论规则

- 每条正文**第一句必须直接给结论**(谁 + 做了什么 + 核心影响),后续段落才展开。
- 禁止以"近日、据悉、据媒体"等铺垫开头。

### 7.2 术语替换表(首批)

出现术语时优先替换为通俗说法;无法替换的首次出现给一句括号解释。

| 术语 | 简版写法 |
|---|---|
| Agent | AI 智能体 |
| 多模态 | 能读图、能听音 |
| OCR | 文字识别 |
| 工作流 | 做事流程 |
| 数据闭环 | AI 结果反哺下一轮教学 |
| 上下文长度 | 一次能读入的信息量 |
| 私有化部署 | 数据装在自己服务器上 |
| 大模型 | AI 大模型(首次全称,之后简称"AI") |

> **待 v0.4 深写:完整行话替换表**。首批仅覆盖高频项,后续由真实周报中的术语卡点驱动扩充。

### 7.3 可读性检查(并入本册,不单独立 Skill)

- 全文可读性检查并入本册写作环节,由 format-all-staff-newsletter 排版时统一执行;**不单独建立检查类 Skill**(Skills 以主文档 9 个核心 Skill 为准,见 skills/registry.md)。
- 检查项:全文以"桃李"称呼公司;句子 ≤40 字;不堆叠英文缩写;期要点 ≤60 字;业务层每条要点 ≤40 字;标题 ≤30 字。
- 成品的正确性与可发布性由 D 执行手册的人工审核 checklist 把关。

## 八、构造示例条目(业务层完整填写)

> **构造示例,非本期真实数据。** 仅演示第三章字段与 5 步写法,不代表任何真实产品功能。

**C-B01 学而思学习机上线"错题归因重练"闭环**

- **一句话要点**:学习机自动归因错题、生成变式题并回测,把课后补弱做成闭环。
- **企业/产品**:好未来 / 学而思 / 学而思学习机
- **教育场景**:课后作业、自习补弱
- **工作流变化**:原流程"学生作业 → 教师批改 → 学生改错"→ 新流程"AI 判错 → 归因 → 生成变式题 → 学生重练 → 下次检测回测"
- **数据闭环**:是。错题与回测结果回流,驱动下一轮变式题与作业规划。
- **来源等级**:S(官网产品页、官方发布会记录)+ A(第三方实测演示)
- **桃李含义**:课后服务可试点同款闭环;变式题生成能力可先行验证是否外采。
- **借鉴分级**:可直接借鉴(变式题生成可购买第三方,归因模型需自行研发)。

**正文(2 段,示例):**

学而思学习机本周上线错题归因重练功能,把"做题—改错—再做"做成了自动化闭环。系统对学生错题做原因归因,按知识点生成变式题;学生完成重练后,下一次检测会带上同样的错因考点回测。

对桃李而言,课后补弱是高度相近的业务场景。该闭环中"变式题生成"已有成熟第三方能力可购买,"错因归因"依赖教育数据积累,需自行研发。建议课后服务团队拆出"重练"一段做 2-4 周小范围试点,验证学生完成率与回测通过率后再决定是否全面跟进。

**桃李含义**:详见上段;试点数据作为"是否立项"的判据。

**来源标注**:来源 1(官网产品页,S)、来源 2(官方发布会记录,S)、来源 3(第三方实测演示,A)。官方宣传与第三方实测的差异点已在附注区记录。

## 九、附注(来源与存疑)

固定出现在建议区之后:

- 列出本期各条目引用的来源清单(按条目标注)。
- 存疑点:官方宣传与实测/案例不一致处、B/C 级来源线索、未能核实的数字,一律如实列出,不掩盖。
- 本区由人工审核人在 D 执行手册节点 4 发布前复核确认;未澄清的存疑点不得进入全员版。
