## 目录结构

```
weekly-report/
├── README.md                          # 本文件:体系导航

│   ├── A-信号数据手册.md               # 信号 JSON schema / 精简状态 / JSONL 信号库 / 去重

│   ├── D-执行手册.md                   # 人机分工 / 每日每周流程 / 简版 QA / 审核 checklist
│   └── E-评分锚点手册.md               # 6 维权重 3 档锚点 / 过滤与强制进入 / 打分案例
├── skills/
│   └── registry.md                     # 9 个核心 Skill 精简注册表
├── signals/                            # JSONL 历史信号库(按周)
├── drafts/                             # 每周草稿
├── published/                          # 发布版快照
└── archive/
    └── v0.2-原稿.md                    # v0.2 全文归档(不覆盖)
```

## 快速上手

1. **想了解方法论**:通读主文档 → 需要评分细则看 E 分册 → 需要流程看 D 分册。
2. **要产出一期周报**:以 **D 执行手册** 为操作入口,按每日/每周流程执行,调用 9 个核心 Skill(见 skills/registry.md)。
3. **想写新闻条目**:按 **C 周报输出规范** 的模板结构写。
4. **想看信号数据**:读 signals/ 下的 JSONL 文件(每行一个信号 JSON)。

## 体系关系

- **主文档**提供骨架(范围/名单/分级/评分权重/模板/节奏/版本管理)。
- **分册**承载可独立演化的细节(信号数据 / 输出规范 / 执行流程 / 评分锚点)。
- **skills/registry.md** 登记 9 个核心 Skill(完整注册表推迟 v0.4)。
- **v0.2 原稿**归档在 archive/,主文档与分册继承其全部有效内容。

## 版本与演进

- 主文档与分册各自独立版本号;修订流程见主文档「方法论版本管理」章节。
- MVP(v0.3)聚焦跑通第一期真实周报;完整深写(27-Skill 注册表、六态状态机、6×5 锚点、多层 QA)由真实周报暴露的问题驱动 **v0.4** 补全。

## 执行模型

人机协作半自动:AI 负责采集/去重/初评/草稿生成;人负责冻结候选池/审核评分/终审发布。AI 不自动冻结、不自动发布。
