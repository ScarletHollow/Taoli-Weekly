# AI周报方法论 v0.3 MVP 落地 + 一期真实周报验证

## Goal

将《桃李未来教育 AI 周报.md》(v0.2)推进为可运行的第一版:MVP 阶段保留方法论骨架(监测范围/名单/信息源分级/评分权重/工作流模板/抓取节奏/版本管理),只实现 **8-10 个核心 Skill**,用**真实的一周数据**跑通「采集→去重→评分→生成→审核→发布」全流程,产出一期真实周报;以真实周报暴露的问题驱动 v0.4 迭代(完整方法论深写推迟到 v0.4,由实际数据校验后再补全)。

## Confirmed Facts (from repo & user)

- 仓库非 git 仓库,除 `.claude/`、`.trellis/` 外仅有一个 `桃李未来教育 AI 周报.md`(v0.2)。无实现代码、无历史周报实例。
- Trellis 历史任务均为另一前端项目,与本任务无关。`.trellis/spec/` 为前端开发规范,不适用于本任务。
- v0.2 缺失环节(规划依据,完整版):输出格式 / 状态流转与历史存储 / 评分锚点 / Skill Registry / 流程↔Skill 映射 / QA gate。
- **范围调整(用户决策)**:不做完整 6 文档方法论 + 27 Skill 全套,改为 **MVP 落地**。理由:方法论是一组假设,在跑出真实周报前,评分锚点、Skill 生命周期、多层评审等重型设计未经真实数据校验;最重的设计恰恰最需要真实数据才能设计对。MVP 先行让完整方法论(v0.4)更对。

## User Decisions

- 交付物形态:**方法论 MVP 文档 + 8-10 核心 Skill + 一期真实周报**。完整方法论(5 分册深写 + 27 Skill 注册表)推迟到 v0.4,由真实周报暴露的问题驱动。
- 读者画像:**公司全员版**。模板含「一句话要点」开首、业务/技术分层正文、桃李可执行建议结尾,每周 5-8 条。
- 语言:中文。
- 目录结构:`weekly-report/` 目录存放周报资产;v0.2 归档为 `archive/v0.2-原稿.md` 不覆盖。
- 历史信号库:**轻量 JSONL**(signals-YYYY-WW.jsonl),支撑去重与跨周对比,不引入数据库。
- 版本演进:主文档「方法论版本管理」章节,分册独立版本号。
- 执行模型:**人机协作半自动**。AI 采集/去重/初评/草稿,人冻结/审核/终审。
- 落地策略(安全默认):非 git 仓库不可回滚,v0.2 归档不覆盖。

## Requirements

- R1: 主文档 v0.3 方法论骨架(监测范围 / 一二级名单 / 信息源 S-A-B-C 分级 / 评分权重表 / 工作流拆解模板 / 抓取节奏 / 最小观察范围 / 版本管理),保留 v0.2 全部有效内容。
- R2: MVP 分册——A 信号数据(信号 JSON + 精简状态流转 + JSONL 库)、C 周报输出规范(全员版模板)、D 执行手册(人机分工 + 周流程 + 简版 QA)、E 评分锚点(6 维权重 + 简版锚点)。
- R3: 实现 **8-10 个核心 Skill**(覆盖采集/去重/评分/生成/审核/发布),登记于精简 Skill 注册表。采集类企业监控用 **可配置的 monitor-education-companies**(默认一级名单 7 家),不用单企业 Skill。
- R4: 用真实一周数据跑通全流程,产出一期真实周报,结构符合 C 分册模板。**去重由 D 分册「每日流程 D5」步骤负责**(AI 读 dedup_key 做事件级去重,不单独立 Skill);**发布由 D 分册「每周流程 节点 4 终审发布」人工操作负责**(AI 不自动发布)。
- R5: 完整方法论深写(27 Skill 全注册表、六态状态机全细节、6×5 全量锚点、多层 QA)推迟到 v0.4,本任务不实现。

- [ ] AC4: 任一角色(编辑者或 AI)按 D 分册流程走一遍,能无歧义地产出一期周报(以本期为验证样本)。
