# 一期真实周报验证(first-real-weekly)

## Goal

用 **最近完整一周** 的公开信息作为数据源,跑通「采集→去重→评分→生成→审核→发布」全流程,产出一期符合 C 分册模板的真实周报(验证样本)。以真实数据校验方法论 MVP,暴露问题驱动 v0.4 迭代。

## Confirmed Facts

- 父任务:08-06-weekly-report-methodology-v03(MVP 落地方向)。
- 依赖:docs-mvp(方法论文档)+ core-skills-impl(9 个核心 Skill)。
- 数据源:最近完整一周(建议 2026-07-27 ~ 08-02)的公开信息,AI 经 WebSearch/WebFetch 采集真实公开事实。
- 读者画像:公司全员版。

## Requirements

- R1: 按 D 分册流程执行:每日采集(7 家一级企业 + 政策 + 模型 + 媒体)→ 去重 → 评分 → 冻结候选池 → 生成初稿 → QA → 人工审核 → 发布。**去重由 D 分册每日流程 D5 步骤负责**(AI 读 dedup_key);**发布由每周流程节点 4 人工操作负责**(AI 不自动发布)。
- R2: 采集覆盖一级名单 7 家(好未来/新东方/猿辅导/作业帮/科大讯飞教育/希沃/网易有道)+ 国内模型 9 家 + 政策源。
- R3: 信号写入 signals-YYYY-WW.jsonl(真实信号,含 source_url/source_level/评分字段)。
- R4: 产出验证期周报(符合 C 模板):期要点开首 / 分层正文 / 桃李可执行建议 / 条数不硬凑。
- R5: 记录流程卡点与歧义,输出「v0.4 迭代建议」清单。

## Acceptance Criteria

- [ ] AC1: 产出一期真实周报(验证样本),含期要点、分层正文、桃李可执行建议。
- [ ] AC2: 信号库 signals-YYYY-WW.jsonl 含真实信号(带 S/A/B 级来源),去重/评分字段完整。
- [ ] AC3: 周报条数合理(不硬凑,允许少于 5 条),每条含来源标注。
- [ ] AC4: 记录流程卡点(≥3 条)并汇总为「v0.4 迭代建议」。
- [ ] AC5: 验证样本按 D 分册流程 + 已实现 Skill 实际跑出(交叉验收)。

## Out of Scope

- 不实现新 Skill(复用 core-skills-impl 的 9 个;如流程暴露缺 Skill,记录为 v0.4 待办)。
- 不深写方法论(推迟 v0.4)。
- 不涉及真实"全员渠道"发布(验证样本以文件形式交付)。

## Dependencies

- 依赖 docs-mvp 提供规范、core-skills-impl 提供可调用 Skill;二者完成后本任务启动。
